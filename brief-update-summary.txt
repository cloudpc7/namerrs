9. SHARED SECURITY & ACCESSIBILITY (all designers)
================================================================================

  OWASP SECURITY:
    Server-side validation on all text; sanitize output
    File upload allowlist: .jpg, .jpeg, .png, .webp
    Validate MIME type AND magic bytes (not Content-Type header alone)
    Server-generated filenames; max 10 MB; Firebase Storage; signed URLs
    Re-encode images; strip EXIF/metadata; reject double extensions
    CSRF / Firebase App Check on save and checkout
    XSS sanitization; Content Security Policy in production
    Access control: users only see own cart designs and orders
    Rate limiting on uploads and form submissions

  VALIDATION MESSAGES (Refactoring UI style):
    Text too long:        "Keep [field] under [N] characters."
    Invalid characters:   "This field allows letters, numbers, and basic punctuation only."
    Save failed:          "We couldn't save your design. Try again."
    Invalid color:        "Enter a valid hex, HSL, or RGBA color."
    Upload failed:        "Upload failed. Check your connection and try again."
    Wrong file type:      "Use a JPG, PNG, or WebP image."
    File too large:       "Image must be under 10 MB."
    Low resolution:       "This image may look blurry when printed." (warning)

  WCAG 2.1 AA:
    Keyboard access for all controls
    Drag-drop alternatives (keyboard/numeric positioning + Reset button)
    Offcanvas focus trap; focus in on open, return on close
    Visible labels or aria-label on every control
    aria-live="polite" for save, flip, step changes
    4.5:1 text contrast; warn if below
    aria-describedby on errors; not color-only
    44 x 44 px touch targets on mobile
    prefers-reduced-motion respected

12b. HTTP STATUS CODE HANDLING (Section 9)
================================================================================

  Express returns consistent JSON error shape:
    { error: true, status, code, message, retryable }

  STATUS CODE MAP:

    200  Success — render data
    201  Created — toast "Saved successfully"
    400  Bad request — inline field errors
    401  Unauthorized — "Please sign in to continue"
    403  Forbidden — "You don't have permission"
    404  Not found — NotFoundPage or empty state + home link
    408  Timeout — "That took too long" + retry
    409  Conflict — "Already updated. Refresh and try again"
    422  Invalid data — inline field errors
    429  Rate limit — "Too many requests" + disable submit
    500  Server error — ServerErrorPage + retry + contact
    502  Bad gateway — "Service temporarily unavailable"
    503  Maintenance — "Doing maintenance. Check back soon"
    504  Gateway timeout — "Server didn't respond" + retry

  REACT/REDUX:
    src/utils/apiClient.js — central fetch wrapper
    src/redux/slices/ui.slice.js — httpStatus, errorMessage, retryable
    Components: HttpErrorBanner, NotFoundPage, ServerErrorPage
    React Router * catch-all → 404
    Global error boundary → 500 fallback
    Never show raw status numbers to users

  STRIPE ERRORS (checkout):
    card_declined → "Your card was declined..."
    insufficient_funds → "Insufficient funds..."
    expired_card → "This card has expired"
    processing_error → "Payment couldn't be processed"
    Network timeout → "Payment service unavailable" + retry

  EXPRESS MIDDLEWARE:
    errorHandler — consistent JSON + status
    notFoundHandler — 404 for unknown API routes
    Log full errors server-side; no stack traces to client in production

18. PRODUCT DESIGNERS — FORM-BASED vs BRIEF SPEC (IMPORTANT)
================================================================================

  WHAT THE BRIEF REQUIRES (Features 1, 7, 9–12):
    Full interactive designers — NOT simple forms.
    Business Cards (Feature 1) explicitly calls for:
      - Clickable card canvas inside offcanvas
      - Text edit, image upload, drag-and-drop onto card
      - Crop, position, background/text colors (hex/HSL/RGBA)
      - Flip front/back, copy front to back
      - Save draft → quantity → scheduling → cart
    T-Shirts and Banners: similar canvas + upload + crop + preview mockup
    Hats, Magnets, Memorial: lighter customizer (text OR logo on mockup)

  WHAT WAS ACTUALLY BUILT (MVP scaffolding):
    Form-based designer steps in src/features/designers/
    Wired through DesignerWizard: Design → Quantity → Schedule → Add to cart
    Per-product forms capture fields (text, colors, size, file name) but:
      - No interactive canvas / artboard
      - No drag-and-drop positioning
      - No image crop UI
      - File inputs record filename only — no Firebase Storage upload yet
      - Business card "copy front to back" is text-only, not layout duplicate

  WHY FORM-BASED WAS USED (NOT A SPEC CHANGE):
    Scope trade-off during "build entire MVP in one pass."
    Drag-and-drop canvas is the largest single feature in the project.
    Form designers unblocked the full commerce pipeline in one session:
      product accordion → offcanvas → wizard → cart → checkout → order API
    while leaving a clear swap-in point at DesignerWizard + registry.js

  WHAT FULL DRAG-AND-DROP REQUIRES (per tier):

    Heavy (Business Cards, T-Shirts, Banners):
      - Canvas/preview layer (DOM or <canvas>) with positioned elements
      - Drag-and-drop library (e.g. @dnd-kit)
      - Upload → Firebase Storage with server-side validation
      - Crop component (e.g. react-easy-crop or custom)
      - Front/back flip with separate artboards (business cards)
      - Design JSON schema persisted on cart items
      - Jest tests + Maestro product-expand-design / add-to-cart flows

    Light (Hats, Magnets, Memorial):
      - Text OR logo placement on product mockup
      - Shared upload + placement primitives from heavy tier
      - Closer to current forms — less canvas work than business cards

  RECOMMENDED BUILD ORDER (to match brief):
    1. Business Card designer — full canvas (establishes patterns)
    2. T-Shirt designer — reuse canvas + upload pipeline
    3. Banner designer — reuse canvas + dimension-aware preview
    4. Hat / Magnet / Memorial — lighter customizer on shared primitives

  CODE LOCATIONS:
    src/features/designers/DesignerWizard.jsx   — wizard shell (keep)
    src/features/designers/registry.js        — maps productId → designer component
    src/features/designers/BusinessCardDesigner.jsx  — REPLACE with canvas implementation
    src/ui/components/DesignerShell.jsx       — offcanvas host (keep)
